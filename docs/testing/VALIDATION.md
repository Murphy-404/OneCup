# 验证记录与用例

版本 v0.3。运行 npm test、npm run build、npm run audit:content。

## 自动化用例

| 场景 | 预期 |
| --- | --- |
| 服务端进程关闭再打开同一 SQLite | 收藏、完整做法和备料保留 |
| 两个设备按同一旧版本写入 | 后写入返回 409，不覆盖；同内容重试幂等 |
| 无效 JSON/材料/快照、损坏数据库 | 报错，不用空数据替换 |
| 在线 WAL 数据库创建备份 | 完整性校验通过，恢复后版本增加 |
| 不可信 Host、跨站 Origin、跨站请求 | 拒绝；显式配置来源可用 |
| 自建未完成草稿 | 可保存，制作前必须补全名称、材料、步骤与引用 |
| 自建基础 2 份，再制作 2 份 | 材料、步骤和备料显示同一用量 |
| 合集来源更新、删除 | 保留旧快照；需明确更新，删除后可制作 |
| 重复条目和容量上限 | 拒绝无效导入与新增 |
| v1 JSON 升级、v2 往返 | 旧内容保留，新字段完整恢复 |
| CI 重建 Docker 容器 | 命名卷数据保留，SQLite 备份/修改/恢复核对成功 |

GitHub Actions 同时在 Windows/Linux 测试。Docker 行为由 docker-smoke 作业实际验证，本地开发机未安装 Docker。CI 运行结果应以对应提交的 Actions 状态为准。

## 浏览器与人工验收

开发中用独立测试数据库验证自建校验、保存、合集添加、手机尺寸布局和重新载入。生产数据不用于测试。

仍需真实手机触控、减少动画/放大、设备断网恢复、真实代理入口、备份复制到另一设备后的恢复演练。配方味道、替代效果、容量适配和食品保存时限不能由自动化测试证明；不将参考内容标记为试做。
